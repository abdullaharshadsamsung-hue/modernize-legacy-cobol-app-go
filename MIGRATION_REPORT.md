### Other review findings
- [warning] **logic-bug**: Ctrl-C no longer stops the program. cmd/accountsystem/main.go wraps the run in signal.NotifyContext(ctx, os.Interrupt), which turns off Go's default handling of SIGINT (exit the process). However, cli.Run in internal/cli/menu.go only checks ctx.Err() at the top of each loop. It then blocks in bufio.Reader.ReadString on stdin, and Service.accept blocks on stdin the same way during credit/debit prompts. When the user presses Ctrl-C at a prompt, nothing visible happens: the process keeps waiting until a full line is entered, and only then exits with code 130. The original COBOL program would end at once on SIGINT. Fix: either stop intercepting SIGINT, or make the reads cancellable, for example by reading in a goroutine and selecting on ctx.Done().
- [info] **duplicate-implementation**: There are two conflicting versions of the PIC 9 choice parser. internal/money/money.go still exports ParseChoice, which keeps the low-order digit and rejects input that is not all digits ("12"→2, "1a"→0), and money_test.go tests it. internal/cli/menu.go's ParseChoice, which the program actually uses, was rewritten by a test-failure fix loop to keep the first character instead ("12"→1, "1a"→1). As a result, the shared helper is dead code that disagrees with live behaviour, and the fix loop moved the CLI away from the GnuCOBOL-faithful version to satisfy a test. Keep a single implementation and check it against golden transcripts from the COBOL program.
